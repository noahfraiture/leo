Ownership boundaries

The app owns settings and lifetimes, the backend owns durable rules, and the session directory owns portable state.

app crate / process

Desktop lifetime

  • Platform settings store and desktop shell
  • RuntimeAvailability and ready-only contexts
  • MediaMTX, RecorderRuntime, and event receiver
  • Root-scoped session and analysis tasks
  • Save writes disk only; restart changes runtime
  • Logging guard and orderly shutdown

backend crate / library

Durable behavior

  • recording::recorder owns FFmpeg children
  • recording::segment validates finalized media
  • session appends and replays the timeline
  • analysis::session orchestrates a completed run
  • analysis::analyzer plans and checkpoints batches

data root / filesystem

Portable truth

  • events.jsonl is the session authority
  • recordings/ contains direct finalized MKVs
  • recording-complete commits the session
  • analysis.json resumes by plan identity
  • No absolute path participates in checkpoint identity

Session commit protocol

A directory is not analyzable merely because files exist. The order establishes what can be trusted.

01

Recorders ready

Every configured camera has produced output media.

02

Start event

events.jsonl is created with camera sampling settings.

03

Action events

Participation and cadence changes append before UI state changes.

04

End and finalize

The end event is written; FFmpeg children stop and valid attempts promote.

05

Completion marker

Only the synchronized zero-byte marker state exposes the ended session to discovery.

Three local desktop E2E scenarios

The opt-in macOS checks drive the complete flow, transient analysis recovery, and recording without preview through the real WKWebView. The fixture pair is test coverage, not a production count restriction. Physical cameras and packaged pointer automation remain separate acceptance work; external-storage loss has a disposable-volume manual drill.
