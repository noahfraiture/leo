# Home Video Player Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a home-page video player with an Alpine.js-driven video dropdown so selecting an uploaded video updates the player source to that video's public endpoint.

**Architecture:** Keep this page-oriented in `home.rs`; the home page already loads uploaded `Video` records and renders the analysis surface. Add Alpine globally in `document()`, render a single selected-video control inside the home page, and use `Video.path` as the browser-facing source so the UI follows the public route generated by the DB model. Preserve the existing checkbox-based `video_selection()` fragment for analysis and delete behavior.

**Tech Stack:** Rust, axum UI route tests, hypertext RSX, Alpine.js, HTMX, DaisyUI/Tailwind generated CSS, Taskfile workflows through `nix develop -c task ...`.

---

## Endpoint Decision

The current code mounts raw video serving at `GET /video/{key}` in `backend/src/http/router.rs`, and uploaded records store `Video.path` as `/video/<uploaded name>`. The user request says `/videos/<video name>`, but that conflicts with the existing collection routes at `POST /videos` and `DELETE /videos/{video_key}`.

Recommended implementation: use `video.path` in the player and keep the existing `GET /video/{key}` route. If the product requirement is truly `GET /videos/{video_name}`, add a separate first task to change `public_video_path()`, the router mount, and the raw-video route tests before implementing the player.

## File Structure

- Modify `backend/src/http/ui/document.rs`: include Alpine.js after HTMX using `defer`.
- Modify `backend/src/http/ui/features/home.rs`: add a page-local `video_player()` render function and call it between upload intake and analysis prompt.
- Modify `backend/src/http/router.rs`: update home-page and upload/delete integration assertions so they cover the player shell and the dropdown source values.
- Modify `backend/src/http/ui/styles.generated.css`: regenerate through `nix develop -c task css:build`; do not edit manually.
- No new route or DB method is needed if the implementation uses `Video.path`.
- Do not modify `AGENTS.md`; existing conventions already cover this work.

- [ ] **Step 4: Add the `video_player()` render function**

Place this private helper after `video_intake()` and before `analysis_prompt()` so public/page flow stays top-down:

```rust
fn video_player(videos: &[db::video::Video]) -> impl Renderable {
    let selected_path = videos.first().map(|video| video.path.as_str()).unwrap_or("");

    rsx! {
        <section
            class="space-y-4 rounded-box border border-base-300 bg-base-100 p-6 shadow-sm"
            "x-data"="videoPlayer"
            data-selected-video=(selected_path)>
            <div class="space-y-2">
                <p class="text-sm font-semibold uppercase tracking-[0.22em] text-base-content/60">
                    "Preview"
                </p>
                <h2 class="text-xl font-semibold text-base-content">"Preview video"</h2>
            </div>

            @if videos.is_empty() {
                <p class="rounded-box border border-dashed border-base-300 p-4 text-sm text-base-content/70">
                    "No videos have been uploaded yet."
                </p>
            } @else {
                <label class="form-control space-y-2">
                    <span class="text-sm font-medium text-base-content">"Video"</span>
                    <select
                        class="select select-bordered w-full"
                        "x-model"="selectedVideo">
                        @for video in videos.iter() {
                            <option value=(video.path.as_str())>
                                (video.name.as_str())
                            </option>
                        }
                    </select>
                </label>

                <video
                    class="w-full rounded-box border border-base-300 bg-base-200"
                    controls="controls"
                    preload="metadata"
                    "x-bind:src"="selectedVideo">
                </video>
            }
        </section>
    }
}
```

- [ ] **Step 5: Add the small Alpine component**

In `backend/src/http/ui/document.rs`, add this inline script after the Alpine CDN script:

```rust
<script>
    (Raw::dangerously_create(
        r#"
        document.addEventListener("alpine:init", () => {
            Alpine.data("videoPlayer", () => ({
                selectedVideo: "",
                init() {
                    this.selectedVideo = this.$el.dataset.selectedVideo || "";
                },
            }));
        });
        "#,
    ))
</script>
```

This avoids embedding JavaScript object syntax directly in a Rust/RSX attribute and keeps the selected default in a normal `data-*` attribute. The quoted Alpine attribute names are intentional: this project enables Hypertext's `htmx` feature but not its `alpine` validation feature, and quoted attribute names bypass validation while still rendering normal HTML attributes.
